## 一、游戏定位

| 项 | 内容 |
|---|---|
| 类型 | 梦幻体育（Fantasy）+ 卡牌模拟对战混合 |
| 核心幻想 | 经营一支由真实 CBA 球员组成的球队，赚金币、爬榜单 |
| 数据底座 | 2026-27 赛季 CBA 官方真实数据：20 队、287 名球员、20 名教练、逐场 boxscore |
| 平台 | 虎扑 App 内 H5，云存档 + 服务器权威校验 |

一句话循环：

```text
获得球员（商店/市场/抽卡） → 排五人首发+教练 → PVE 模拟赛季赚金币
→ 真实赛果结算身价/竞猜 → 卖出/再签约 → 排行榜
```

## 二、数据管线（原版怎么弄数据的）★本文重点

### 2.1 三层数据来源

```text
CBA 官方公开接口（AES-128-ECB 加密前端接口）
   ↓ 抓取/解密/整理（原开发者服务端做）
虎扑云 tcloudbase 上的「官方数据快照」
   ↓ /official-feed?date=（CBACloud.request）
游戏客户端 CBAPlayerData 快照仓库
   ↓ 纯客户端公式
范特西得分 / 身价 FI / 行情报价 / 每日预测开奖
```

### 2.2 快照格式（player-feed.json = 快照样例）

顶层结构：

```json
{
  "teams": { "29115": "北京首钢", ... },          // 20 队 ID→名称
  "season": "2026-2027",
  "source": {
    "name": "CBA official data",
    "scope": "regular-season-and-preseason",
    "matchTypes": [{ "id": 1, "name": "常规赛" }, { "id": 3, "name": "季前赛" }],
    "responseFormat": "public-frontend-AES-128-ECB"
  },
  "players": {
    "cba-679408": {
      "id": "cba-679408", "name": "王哲林", "teamId": "29125", "teamFull": "上海久事",
      "officialId": "679408", "dataSource": "cba-official",
      "gamesCoverage": "complete-season",
      "games": [ { 逐场 boxscore } ],             // 常规赛逐场
      "preseasonGames": [ ... ]                    // 季前赛逐场
    }
  }
}
```

单场 boxscore 字段（新游戏接口规格沿用此结构）：

```json
{ "id": "100110655", "date": "2026-10-16",
  "stats": { "min":27.05, "pts":14, "reb":18, "oreb":4, "dreb":14,
             "ast":0, "stl":0, "blk":0, "turnover":2, "fouls":2,
             "fgMade":4, "fgAttempt":8, "ftMade":6, "ftAttempt":8,
             "threeMade":0, "threeAttempt":0 },
  "isHome": true, "played": true, "starter": true,
  "teamId": "29125", "teamScore": 102, "opponent": "深圳马可波罗",
  "opponentId": "29131", "opponentScore": 68,
  "status": "final", "officialStatus": 4,
  "matchTypeId": 1, "matchTypeName": "常规赛第1轮",
  "scheduleTime": "2026-10-16 19:35:00" }
```

要点：
- `officialStatus: 4` = 完场；非 4 = 未开赛/进行中（预测"开赛前可下注、开赛即停"靠它）。
- `starter`、`min` 是 P1 伤病/轮停与临场状态系统的现成数据源。
- 球员能力值不在 feed 里，在客户端静态目录（见 2.4）。

### 2.3 在线同步机制（cba-runtime-06 附近，第 4754 行起）

- `CBACloud.request('/official-feed?date=')` 拉取，服务端返回**整包快照**（非增量）：
  `{schedules, players, season, updatedAt, coverage, syncStatus}`。
- 客户端校验三关：格式有效（schedules 数组 + players 对象 + updatedAt 可解析）→ 赛季一致 →
  `updatedAt` 比本地新才执行 `CBAPlayerData.update(feed)`。
- 同步时机：启动、网络恢复、窗口聚焦、visibilitychange、定时轮询。
- 失败进入 `fallback` 状态，展示"官方数据同步暂不可用，稍后自动重试"，本地快照兜底继续玩。
- 快照更新后顺手触发 `CBAFantasyUI.refreshMarket({invalidate:false})` 刷新行情。

### 2.4 静态目录（随包内置，不走网络）

- 球员能力值表：46–90 分，人工校准（校准表 SHA256 校验串内置），`fixed-catalogue` 固定目录，比赛中不变。
- 基础身价 180–900 金币、档位 tier 0–3（白/绿/蓝/紫）、合同 A–D、外援标记 59 人。
- 结论：**"谁会打球"是静态的，"最近打得多好"是动态的**——两层分开，这是原版数据设计的核心思路。

### 2.5 对新游戏的启示

1. 原版服务端只干一件事：**把加密官方数据洗成明文快照**。新游戏里对应"你的三个接口"（/cba/players、/cba/meta、/cba/games）。
2. 原版返回整包快照是因为有自建服务端缓存；新游戏受 Lamps request 通道 30s/体积限制，按日拆包是必须的改造。
3. `updatedAt` 单调合并 + 失败 fallback 本地，这套容错模式直接照搬。

## 三、玩法系统逐个拆解

### 3.1 球员获取（三条通道）

**每日商店（recruit）**
- 每天确定性生成 5 名球员：1 名 D 类合同 + 1 名外援 + 3 名其他（`selectShop()`，按日期+ID 的 FNV 哈希，**纯客户端可复现，无需服务器**）。
- D 类/外援享 7/8/9 折（`discountFor()` 哈希决定）。
- 翻卡确认制，每日限刷 10 次，刷超限可看激励视频。
- 设计意图：每日回访钩子 + "今天有谁"的签到感。

**签约市场（market）**
- 球员/教练按"股"交易，每人限持 1 股。
- 价格随真实赛果浮动：球队胜场 +5%、负场 −5%，区间 [初始价 50%, 120%]，固定起点核算防触底套利。
- 另有 `computeQuote`：FI 每 10000 点调 0.05 比率，带最低价保护。
- 可随时按当前行情卖出回收金币。
- 设计意图：**本作最强记忆点**——低买高卖正在爆发的真实球员。

**招募抽卡（draw）**
- 招募卡单抽/五连，新手免费五连保底蓝卡；金币补抽 200/五连、300/单抽。
- 评价：与商店/市场功能重叠，是第三条冗余通道（改版砍掉金币抽卡）。

### 3.2 阵容

- 5 人首发 + 1 教练 + 战术风格。
- 校验：五名不同球员、同球员不同版本不能同时出战、不可用球员不能首发。
- 替补无上限。战力按首发能力与位置契合计算。

### 3.3 PVE 赛季（征战之路）

- 26 场模拟赛季 + 训练副本（按 20 队轮换）。
- 对手 = 20 支 CBA 球队的"模拟首发"（按名单位置与能力生成，仅本地对战）。
- 10 套进攻 × 10 套防守战术克制：克制时对方防守效果减半，被克制增强 50%。
- 教练等级与契合度加成（`cba-coach-power-r28`）。
- 2 倍速 / 直接结束。胜利 50–100 金币、失败 20 金币。
- 评价：战术克制有深度，但对手是死数据（改版换玩家阵容快照）。

### 3.4 每日预测（fusion）

- 竞猜当日真实 CBA 比赛胜负：`猜中返还 投入 × 比赛倍率 × 道具倍数（含本金）`，猜中才有回报。
- 开赛前可下注，开赛即停（靠 `officialStatus`/`scheduleTime`）。
- 道具卡可加倍。页面明示"金币仅用于游戏，无奖品、无提现"。
- 原版由服务器结算；新游戏改客户端按快照赛果核对（弱权威）。

### 3.5 养成

**合卡强化（fuse）**：2–5 张同档合成，能力加成上限 +100，成功率按档位递减 `[.65, .4, .18, .06]`，幸运卡 +10%，橙卡封顶。
**碎片合成**：9 张同球员同版本碎片博一张卡，成功率 `[1, .8, .5, .2, .06]`，失败不返还（改版砍掉）。
**教练升级**：同名 Lv.1 卡喂级，上限 Lv.10；教练无能力值只有身价。

### 3.6 经济系统（单一金币，全对账）

| 产出 | 数值 |
|---|---|
| 开局 | 500 |
| 新手任务 5 步 | 5×300 = 1500 |
| 7 日签到 | 500+200×5+500 = 2100 |
| PVE 胜/负 | 50–100 / 20 |
| 预测猜中 | 本金 × 倍率 × 道具倍数 |
| 卖出球员/教练 | 按行情报价 |
| 邀请 | 上限 15 次 ×1 招募卡 |

| 消耗 | 数值 |
|---|---|
| 签约 | 市场行情价 / 商店折扣价 |
| 抽卡补价 | 200/300 |
| 合卡 | 10 金币/级 + 材料 |
| 预测下注 | 自定投入 |
| 刷商店 | 看广告（非金币） |

道具：招募卡、幸运卡、道具卡（预测倍数）、碎片、卡包、金币包。

### 3.7 社交与竞技

- 排行榜：服务器权威，战力/价值双榜，前 50，同分先到者优先；价值榜每日 00:00 更新。
- 无真人 PVP（Colyseus 加载了但 0 次调用）。
- 阵容/战报分享海报（虎扑社区场景）、邀请码。

## 五、关键公式备查

```text
范特西得分 = pts + 篮板×(本土1.3/外援1.2) + 助攻×(本土1.7/外援1.5) + 抢断×3 + 盖帽×3 − 失误×1.5

比赛得分 gameScore = pts + 0.4×命中 − 0.7×出手 − 0.4×罚球丢分 + 0.7×前场板
                    + 0.3×后场板 + 0.7×助攻 + 抢断 + 0.7×盖帽 − 0.4×犯规 − 失误

身价 FI：abilityFiPerPoint = 10000；范特西乘数 本土 2500 / 外援 2000；
        赛果修正 winUp 1.1 / winDown 0.6 / lossUp 0.6 / lossDown 1.1
行情：胜场 +5% / 负场 −5%，区间 [50%, 120%] 初始价

伤病概率（参考）= .65 + (100−耐久)×.025 + (100−健康)×.018，夹 [.25, 5.5]

商店折扣 = (7 + hash(日期,球员ID) % 3) / 10   ← 纯客户端确定性
合卡成功率 = [.65, .4, .18, .06]；碎片 = [1, .8, .5, .2, .06]
```

## 七、强弱点结论（新游戏设计的出发点）

**强（必须继承）**
1. 真实数据驱动的梦幻体育正解——同类 H5 稀缺。
2. 行情市场"低买高卖"记忆点。
3. 经济闭环完整、单货币全对账，确定性商店免服务器。
4. 工程可读、防御校验成熟、数据容错（快照合并+fallback）设计好。

**弱（改版要解决）**
1. 无真人对战，赛季对手是死数据 → 异步 PVP。
2. 能力值固定，长线成长感弱 → 临场状态 + 伤病/轮停。
3. 获取通道冗余（商店/市场/抽卡三条）+ 碎片失败全损 → 减法。
4. 中后期无事可做（只有 7 日签到+新手任务）→ 周任务/赛季目标。
5. 服务器强绑定虎扑 → Lamps 平台能力 + 自有轻接口。

## 一、结论速览

| 环节 | 原版（虎扑《CBA梦幻经理》） | 现游戏（《签下整个CBA》Lamps 版） |
|---|---|---|

## 二、原版数据来源

### 2.1 官方接口（CBA 官方数据站）

- 站点：`data-server.cbaleague.com`
- 加密：请求体/响应体 **AES-128-ECB**，密钥 `uVayqL4ONKjFbVzQ`（官方前端明文硬编码）
- 请求头：`isEncrypt: encrypt`

核心端点（逆向所得，均已在官方源验证）：

| 端点 | 用途 |
|---|---|
| `GET /api/schedules/day?day=YYYY-MM-DD&auto=0` | 某日赛程与赛果（`status: 4` = 完场） |
| `POST /api/player-match-datas/data-count {scheduleId}` | 单场比赛的全部球员技术统计 |
| `GET /api/schedules/getPlayersByScheduleId/{id}` | 报名名单（含 `isInjury` 伤病标记） |
| `GET /api/players/all` | 全联盟球员目录 |

### 2.2 抓取方式

原作者**在服务端**抓取：其腾讯云开发（tcloudbase）里的云函数定时/按需调用上述接口，解密后归一化，生成“球员 + 赛程 + 技术统计”快照。客户端从不直连 CBA 官方站。

现游戏保留了同一套抓取与解密能力（`relay/scf/` 云函数与本地验证脚本），只是**运行期不再由客户端访问**。

## 三、原版数据存储

### 3.1 云端

- 腾讯云开发环境：`envId: app-1b8c1d4749-...`，接口基址 `https://app-1b8c1d4749-....ap-shanghai.app.tcloudbase.com/api`
- 云函数内存/数据库中维护：球员快照、赛程、行情（价格模型输入）、排行榜数据
- 静态兜底：`player-feed.json` 另存腾讯云静态托管（`static.cloudbase.net`）

### 3.2 客户端

- 进游戏后整包快照进入内存（`CBAPlayerData.getSnapshot()`），派生出场均、价格、战力
- 本地存档（IndexedDB / localStorage）保存球队、金币、阵容、预测记录等**玩家状态**
- 虎扑登录体系串起账号，云存档由作者云函数权威写入

### 3.3 快照结构（现游戏包内同构）

`player-feed.json`（约 1MB）：

| 字段 | 内容 |
|---|---|
| `players`（287 人） | 球员档案、场均、逐场数据行（894 行）、基准价 |
| `schedules`（490 场） | 2026-10-09 ~ 2027-04-07 全赛季赛程，`final` 40 场 |
| `teams`（20 队） | 队名、队徽、客场球衣色 |
| `coverage` | 覆盖度：`completedGames: 40`、`completeThrough: 2026-10-18`、`missingBoxScores: []` |
| `updatedAt` | **2026-10-19T03:00:19Z（北京时间 10-19 11:00）** |

## 四、原版调用与更新链路

```
[作者云函数] --定时抓取--> CBA官方加密接口
      |  归一化快照
      v
[tcloudbase API / 静态托管]
      ^
      | 请求经【虎扑平台代理能力】：ColorboxAI.cloud.request({envId, auth})
      | 静态快照：ColorboxAI.request（域名白名单 hupu.com / static.cloudbase.net）
      |
[游戏客户端] 进入游戏 → 整包快照拉取 → 内存派生 → UI 渲染
```

关键点：**域名能用是因为请求走平台 SDK 通道、环境在平台侧登记**——不是裸连。

刷新时机（原版）：启动、页面聚焦、切回前台、间隔轮询；每次都是整包重拉，体验代价是“进游戏几十秒才出数据”。

## 五、现游戏（Lamps 版）数据链路

```
[构建/服务端抓取能力]（relay/scf 云函数，保留但运行期不连）
        |  人工触发，导出快照
        v
[player-feed.json 打包进 ZIP] ---- Lamps 运行期零外部请求 ---- [游戏客户端]
        |                                                      |
        |                                                      +--> localStorage 存档（球队/金币/阵容/预测）
        |                                                      +--> Lamps 云存档 saveGameProgress（game_payload）
        |                                                      +--> Lamps 排行榜 dataLoad（战力/价值/阵容池/预测榜）
```

- 数据装载：`cba-launch.js` 预载 + 包内快照进入 `CBAPlayerData`
- 玩家状态：`localStorage`（`cba-fantasy-release-v1:r13-isolated-practice`）+ Lamps 云存档双写
- 榜单：`cba-rank-sync.js` 三榜（power / value / predict），`dataLoad` 带昵称与首发阵容
- **第三方中继已移除**（Lamps 域名门禁整改）：`RELAY_URL`、`fetchRelay`、XHR 回退、阵容外传全部删除

### 5.1 赛果在线同步（2026-10-31 接入）

数据源：平台已备案代理

```
https://lamps-api.hoorahgo.com/cloud-proxy/app-1b8c1d4749-d8gmk54gz5fc75d0d-1252166086.ap-shanghai.app.tcloudbase.com/api/official-feed
```

实现（`cba-lamps-glue.js` → `installOfficialFeedSync`）：

1. **只走平台通道**：`LampsGame.request({url, method:'get'})`；无 `fetch`/`XHR` 直连，也无任何回退分支。
2. **启动顺序**：等待 `CBAPlayerData` 就绪 → 回放 `localStorage['cba-official-feed-v1']` → 2.5s 后联网同步；之后每 30 分钟、窗口聚焦/回前台（>5 分钟）补拉。
3. **响应解析**：兼容 `{data: ...}` 多层嵌套、URL 编码字符串、纯对象三种形态，校验 `players` + `schedules` 后采用。
4. **保护性合并**（`mergeSnapshot`）：赛程按 `id` 并集（接口只给增量也不丢整季）；`coverage` 只前进不后退；`teams` 缺失时保留原值。
5. **应用**：`CBAPlayerData.update(merged)`，触发 `cba:player-data-updated`、`cba:data-date-changed` 与行情刷新；本地调试（无 `LampsGame.request`）只用包内快照。
6. **降级**：请求失败/结构不识别 → 保持当前快照，不影响玩法。

页面提示同步改为“真实数据快照更新至 {日期} · 联网自动同步”。

**合规终检**（ZIP 内 135 个 js/html/json 全量扫描）：无 XHR/fetch、无 `tencentscf`、无未备案外域；同时把 bundle 内 194 处虎扑/虎扑图片域名（仅来源标注字符串、`avatarSourceUrl` 从未被读取）全部改写为本地 `data-source.html#…` 标记。

## 七、补齐路线

### 路线 A：构建时更新（立即可做，零运行期请求）

1. 写 `recon/refresh-feed.js`：复用 `relay/scf` 已验证的抓取+解密代码
2. 流程：拉官方 → 解密 → 合并进 `player-feed.json` → 更新 `coverage/updatedAt` → 打包
3. 实时性 = 发版节奏（建议每天或每个比赛日后发版）
4. 优点：天然合规；缺点：数据延迟 ≤1 个发版周期

### 路线 B：域名备案（要“当天内实时”）

1. 向 Lamps 提交中继域名备案/白名单申请
2. 通过后按平台 `LampsGame.request` 通道恢复增量拉取（代码结构可复用，只允许平台通道）
3. 实时性可到 10 分钟级

~~先上 A，同时并行推进 B~~ → **2026-10-31 已通过平台代理落地（5.1）**，A/B 均不再必需；保留 `refresh-feed.js` 作为平台代理故障时的构建期兜底即可。

# 06 P1 状态层记录（伤病/轮停 + 临场状态）

> 完成日期：2026-10-29。模块：`cba-form-r29.js`（追加于 cba-startup.js 末尾）。
> 浏览器实测：287 名球员全量计算 17ms（按日缓存），控制台 0 错误。

## 一、设计（按 03 策划文档 §3.4 落地）

| 状态 | 判定（全部来自 CBAPlayerData 快照的真实 boxscore） | 效果 |
|---|---|---|
| 火热 hot | 近 3 场范特西得分 ≥ 赛季场均 ×1.2（需 ≥3 场） | 临场能力 +5% |
| 冰凉 cold | 近 3 场 ≤ 赛季场均 ×0.8 | 临场能力 −5% |
| 轮休 rested | 上一场出战但 min < 15 | 标记（PVE 上场惩罚后续接入） |
| 伤停 injured | 最近 2 场球队比赛连续未出战 | 标记（首发限制后续接入） |
| 正常 | 其余（含数据 <3 场） | ±0 |

- 数据源：`CBAPlayerMetrics.normalizeGames(games, player, {asOf})` → 行含 `date/completed/didNotPlay/stats.min/fantasy`。
- 预期量级（2026-10-29 快照实测）：hot 1 / cold 3 / rested 50 / injured 0 / normal 233。
- **纯派生数据，不进存档**——零存档改动、零迁移风险；每日缓存按北京时间日期失效。

## 二、接入点（本阶段 1 个）

**`effectiveCardRating_` 乘数**（cba-startup.js 单行补丁）：

```js
effectiveCardRating_=(e,t,n)=>Math.round(cardAbility_(e,n)*positionMultiplier_(e,t)
  *((window.CBAFormR29&&window.CBAFormR29.effectiveMultiplier(e.playerId))||1))
```

此函数是全游戏战力的单一出口：首发面板显示、一键布阵、PVE 模拟快照全部经过它——
**火热球员在阵容里真实变强、冰凉真实变弱**，且市场和状态联动（身价已随赛果浮动，现在能力也会）。

实测：阿不都沙拉木（火热）乘数 1.05、艾孜麦提（冰凉）0.95、王哲林（正常）1.0。

## 三、API（window.CBAFormR29）

| 方法 | 说明 |
|---|---|
| `status(playerId)` | `{kind:'hot'\|'cold'\|'injured'\|'rested'\|'normal', delta, label, version}` |
| `effectiveMultiplier(playerId)` | 1.05 / 0.95 / 1 |
| `describe(playerId)` | 中文标签（'火热'/'冰凉'/'伤停'/'轮休'/''） |
| `POLICY` | 全部阈值（version: form-r29-20261029） |

## 四、后续（P1-b 待办）

1. **UI 徽章**：市场页/球员卡/首发位显示状态角标（火焰/雪花/医疗十字），让"为什么强"可见——抄底冰凉、抛售火热成为显性策略。
2. **伤停首发限制**：`beginMatch` 的"首发阵容包含不可用球员"校验加入 injured 拦截 + 阵容页置灰。
3. **轮休 PVE 惩罚**：模拟引擎中 rested 球员出场时间/得分概率减半。
4. **伤停判定加固**：若数据源对 DNP 球员整行缺失（而非 played:false 行），连续缺席检测会漏判——等 M2 接口数据稳定后用真实缺失样例校准。
5. rested 50 人偏多（轮换边缘球员 min<15 属常态），P1-b 可加"背靠背豁免"或把阈值降到 10 分钟。

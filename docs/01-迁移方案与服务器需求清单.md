## 一、玩法取舍（已定）

### 保留（核心资产）
| 系统 | 说明 |
|---|---|
| 真实数据管线 | 287 名真实球员 + 逐场真实赛果驱动身价（FI）与竞猜 |
| 签约市场（股票式行情） | 低买高卖，价格随真实赛果浮动 |
| 每日预测 | 竞猜当日真实 CBA 比赛，每日回访钩子 |
| 战术克制 PVE | 10 套进攻 × 10 套防守，26 场赛季 |

### 砍掉
| 系统 | 理由 |
|---|---|
| 碎片合成（9合1） | 与商店/市场获取通道重叠，失败全损体验差 |
| 金币招募抽卡 | 第三条冗余获取通道；保留免费首招五连作为新手福利 |
| 邀请码体系 | 虎扑社交链路产物 |
| 多代经济配置（r13/r24/r27/r28） | 收敛为单一版本号，消除版本债 |

### 升级 / 新增（改版顺序）
- **P0** 砍上述系统、收敛经济配置、去虎扑化（gate/云存档/分享/下载引导全部摘除）
- **P1** 伤病/轮停系统 + 球员临场状态（hot/cold，基于真实出场数据，±5%）
- **P2** 异步 PVP：用其他玩家阵容快照做赛季对手（优先用排行榜 dataLoad 承载阵容快照，免服务器）
- **P3** 周任务 / 赛季目标

## 二、迁移架构：三层分工

### 第 1 层：Lamps 平台能力（直接用，无需服务器）
| 原虎扑依赖 | Lamps 替代 | 说明 |
|---|---|---|
| tcloudbase 云存档 `/game/save` | `LampsPlatform.saveGameProgress` / `getGameProgress` | 每用户最新一条进度。存档需精简（见下） |
| 排行榜 `/leaderboard/submit` | `LampsPlatform.submitLeaderboardScore` 等 | 战力榜 `gameRankType:"power"`、价值榜 `"value"`；周榜用 `"value-W2026W44"` 式按周滚动 |
| vatask 激励视频（商店刷新） | `LampsGame.showRewardedVideo({source:"shop-refresh"})` | 只认 `res.ok === true` 后发奖 |
| ColorboxAI 身份 | 无需 | userId 由平台托管在存档/榜单内，无登录环节 |
| Colyseus（原本未用） | 移除 | 不打包 |

**存档精简方案**（进度对象体积未知，按保守设计）：
- 球员持仓不存整卡，存 `[{id, ver, fuseBonus, count}]`；
- 市场持仓存 `{playerId: {buyPrice, shares}}`；
- 赛季进度、金币、签到日期、每日预测待开奖单全量存；
- 每次结算后保存（PVE 打完、签约/卖出、预测下注、签到）。

### 第 2 层：纯客户端本地逻辑（无需服务器）
| 系统 | 为什么可以本地 |
|---|---|
| 每日商店 | 按日期+球员ID 哈希确定性生成（原版就是 FNV 哈希，客户端可复现） |
| 折扣、合卡、PVE 模拟 | 原本就在客户端算 |
| 身价行情 | FI 公式（`cba-fantasy-data.js`）+ 赛果数据本地核算 |
| 7 日签到 | 日期判断写入存档（接受单机级弱校验） |
| 每日预测结算 | 赛果来自第 3 层数据接口，客户端核对开奖（单机经济无提现，弱权威可接受；如要防刷见 P1 可选服务端） |

### 第 3 层：你的服务器（经 `window.LampsGame.request` 调用）
唯一硬依赖是 **CBA 数据源**。其余为可选增强，见需求清单。

## 三、服务器需求清单（给接口方）

### 通用约束（Lamps request 通道决定）
- 调用方式：游戏内通过父页面代理发 GET/POST，**不能用 fetch/XHR**，无 CORS 问题，但 URL 必须 https 公网可访问。
- 响应体在通道内被 URL-encode 传输，且通道 30 秒超时 → **单次响应体积务必控制在小几十 KB**，大文件拆分/增量。
- 业务约定：响应 JSON 建议统一 `{"code":0,"msg":"","data":{...}}`，`code:0` 为成功。
- 免鉴权可先跑通（单机经济无真实资产）；后续要防刷再加签名/时间戳校验。

### P0 必须：CBA 数据接口（3 个）

**1. 球员静态目录**（低频变化，建议直接挂 CDN 静态 JSON）
```
GET https://<host>/cba/players
```
返回：287 名球员 + 20 教练目录，字段沿用原 `player-feed.json` 的球员对象结构
（`id/name/teamId/position/contract/tier/foreign/basePrice/ability/...`），外加：
```json
{ "season": "2026-2027", "version": "20261028", "players": [...], "coaches": [...] }
```
说明：`ability` 能力值表来自校准表，后续如重新校准，换 version 即可。

**2. 赛程/日期索引**（每日小请求，游戏启动时调）
```
GET https://<host>/cba/meta
```
返回：
```json
{ "season": "2026-2027", "lastUpdated": "2026-10-28",
  "dates": [{ "date": "2026-10-27", "finished": true, "gameCount": 5 },
            { "date": "2026-10-28", "finished": false, "gameCount": 3 }] }
```
说明：游戏据此知道哪些日期有完场赛果可结算，避免拉整月数据。

**3. 按日比赛数据**（每日预测结算 + 身价核算的燃料）
```
GET https://<host>/cba/games?date=YYYY-MM-DD
```
返回：当日每场比赛 + 每名出场球员的 boxscore，字段沿用原版逐场结构：
```json
{ "date": "2026-10-28", "games": [
  { "gameId": "...", "home": "teamId", "away": "teamId", "homeScore": 102, "awayScore": 98,
    "officialStatus": 4,
    "stats": [{ "playerId": "...", "min": 32, "pts": 21, "reb": 8, "oreb": 3, "dreb": 5,
      "ast": 5, "stl": 2, "blk": 1, "turnover": 3, "fouls": 4,
      "fgMade": 8, "fgAttempt": 15, "ftMade": 4, "ftAttempt": 5,
      "threeMade": 1, "threeAttempt": 4, "starter": true }] } ] }
```
说明：
- 未完场比赛 `officialStatus` 给非 4（如 0=未开赛）并带开赛时间，用于"开赛前可下注、开赛即停"。
- 单日全量约几十 KB，符合通道体积约束；客户端缓存已拉取日期。

### P1 可选：服务端权威预测（仅当要防刷时提供）
```
POST /cba/predictions   { date, gameId, pick, stake, multiplier }   → 下注（服务端记）
GET  /cba/predictions/me?date=...                                 → 我的注单
POST /cba/predictions/settle                                      → 或由服务端赛果核对后自动结算
```
默认方案是客户端结算（第 2 层），此组接口可先不做。

### P2 可选：玩家阵容池（异步 PVP 对手源，二选一）
- **方案 A（免服务器）**：提交排行榜分数时把阵容快照放 `dataLoad`（普通对象），拉榜取前 50 名阵容做对手池。零接口，但对手池上限 = 榜上 50 人。
- **方案 B（服务器）**：
```
POST /cba/lineup     { lineupSnapshot }          → 上报阵容快照
GET  /cba/lineup/random?count=10                 → 拉随机对手阵容
```
玩家量大后再上 B。

### 明确不需要的接口
- ~~登录/身份~~（Lamps 托管）、~~存档~~（LampsPlatform）、~~排行榜~~（LampsPlatform）、~~广告校验~~（Lamps 父页面权威）、~~商店/签到/行情~~（本地确定性）。

## 五、风险与待确认
1. **Lamps 存档体积上限未知** → 按精简方案设计；首次实测存/读一轮确认。
2. **request 通道响应体积** → `/cba/games` 单日返回实测压测；超限则再拆按场。
3. **价值榜"每日 00:00 更新"** → Lamps 榜无定时重置，改用按周/按期 `gameRankType` 滚动，日更新语义改为"取快照时刻的价值"。
4. 数据接口的更新时效：每日完场后多久可拉到（影响预测开奖提示文案）。

## 二、关键发现（降低风险的重要事实）

1. **原版 v6 的抽卡/碎片/背包 UI 本来就是死代码**：
   - 背包视图（`bp-root`，含碎片/道具/球员/卡包/金币/教练六页签）在原版中**没有任何挂载点**（`my` 组件从未被调用）；
   - 抽卡派发器（`{type:'draw'}` 的 UI 端）同样无可达入口，原版已从导航移除；
   - 所以"新秀免费五连"在原版线上实际不可达。我们的改动等于：清死代码 + 断奖励流，让这些系统彻底不可复活。
2. **教练系统不受影响**：`drawCoach` 在 0 张招募卡时自动走纯金币路径（`e=Math.min(drawTickets,count)`），另有 `coach-buy` 直接金币签约，双通道保留。
3. **邀请码彻底休眠**：唯一入口（首页分享按钮）已删；`jv` 好友分享面板只在存在分享链接时渲染（Lamps 上永不渲染）；邀请模块 `CBAInviteUI` 成为死代码，不打包删除（无体积紧迫性）。

## 三、经济配置收敛决策（r29 不落地）

原计划把 economy-r13/r27、pricing-r27、stock-r24、coach-r28 多代版本号收敛为 r29。**执行时决定放弃**：
- 版本号深度参与存档校验/迁移链（`migrateState`、`shopPolicyVersion`、`pricingVersion` 同步检查等），改名收益仅是观感，风险是全线存档兼容问题；
- 决策：保留现有版本号，将其视为**模块版本标识**而非版本债；新玩法（P1 状态层）启用新模块前缀（如 `cba-form-r29.js`），不再往旧版本号上叠。
- 此决策记录于本文档，03 策划文档中"收敛 r29"条款按此理解执行。

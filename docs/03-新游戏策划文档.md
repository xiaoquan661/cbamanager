## 一、游戏概念

| 项 | 内容 |
|---|---|
| 游戏名 | CBA梦幻经理2（暂定，可再议） |
| 平台 | Lamps 小游戏平台 |
| 分类 | 阵容组建 / 梦幻体育 |
| 入口 | 根目录 `index.html`（硬性要求，已满足） |
| 一句话 | 用真实 CBA 球员的真实表现经营你的球队：签约、抄底、竞猜、登顶 |
| 核心差异 | 赛果来自真实 CBA——你的球员今天打得好不好，是现实决定的 |

**设计支柱**（继承原版三个强点，补一个原版没有的）：
1. 真实数据驱动（赛果、身价、竞猜全部由现实决定）；
2. 行情市场——低买高卖是第一记忆点；
3. 每日回访——商店、预测、比赛天天有理由打开；
4. **新增：经理的功课**——伤病、轮停、临场状态逼你真正"经营阵容深度"，这是原版缺的策略压力。

## 二、核心循环

```text
每日商店签到看行情 → 调整首发（避伤停/追热门）→ PVE/PVP 模拟比赛赚金币
→ 真实赛果结算：身价浮动 + 预测开奖 + 临场状态刷新 → 卖出/抄底/再签约
→ 周目标结算 → 排行榜
```

节奏：日更（商店/预测/状态）+ 周更（周榜/周任务）+ 赛季级（征战之路 26 场）。

## 三、系统设计

### 3.1 球员获取（从三条砍成两条）

| 通道 | 规则 |
|---|---|
| 每日商店 | 保留原版：每日确定性 5 人（1 D类 + 1 外援 + 3 其他），7–9 折，限刷 10 次，超限看广告 |
| 签约市场 | 保留原版：1 人 1 股，价格随真实赛果浮动（胜 +5%/负 −5%，区间 [50%,120%]） |
| ~~招募抽卡~~ | 砍。新手免费五连保留一次作福利，之后不再有抽卡入口 |
| ~~碎片合成~~ | 砍 |

### 3.2 养成（简化保留）

- **合卡强化**保留：2–5 张同档合成，+能力上限 100；改动：失败**返还一张材料**（原版全损）。
- **教练**保留：20 名真实教练，同名卡喂级 Lv1–10，攻防战术加成。
- 球员能力值仍是静态目录（46–90）——**动态部分移交给 3.4 临场状态**。

### 3.3 阵容与 PVE

- 5 首发 + 1 教练 + 战术，校验规则不变。
- 征战之路 26 场 + 训练副本，战术克制不变（克制减半/被克增强 50%）。
- 对手池升级见 3.6。

### 3.4 ★新系统：状态层（P1，本作最大的玩法增量）

球员在静态能力之外叠加一个**动态状态**，每日随真实表现刷新：

| 状态 | 判定（基于 boxscore） | 效果 |
|---|---|---|
| 火热 hot | 近 3 场 gameScore 高于赛季场均 20%+ | 临场能力 +5%，市场页有火焰标 |
| 正常 | 默认 | ±0 |
| 冰凉 cold | 近 3 场低于场均 20%− | 临场能力 −5% |
| 伤停 injured | 数据源缺席标记/连续 DNP | 不可首发 |
| 轮休 rested | 有上场但 min < 15 且非背靠背主力模式 | 上场概率减半（PVE 中） |

- 判定全部来自 `/cba/games` 的 `min/pts/starter/played` 等字段，**无新增接口**。
- 与市场联动：火热球员身价本来就会涨（真实赛果），状态标让"为什么涨"可读——**抄底冰凉、抛售火热**成为显性策略。
- 与阵容联动：伤停球员不能首发，逼你保留替补深度（原版替补无意义，现在有意义了）。

### 3.5 每日预测

规则不变（猜胜负、开赛前可下注、倍率卡）。改动：
- 结算改**客户端核对**：拉当日 `/cba/games`，`officialStatus==4` 后按真实比分开奖（单机经济，弱权威可接受）。
- 断网兜底：注单随存档保存，下次联网补开奖。

### 3.6 征战之路的对手升级（P2）

- 第一阶段（免服务器）：排行榜 `dataLoad` 里携带阵容快照，对手池 = 榜上玩家阵容前 50。
- 第二阶段（玩家量大）：服务器 `/cba/lineup/random` 随机对手池（接口已列入可选清单）。
- 赛季结构：26 场常规赛 + 季后赛种子（按常规赛排名打前 8 名对手阵容的淘汰赛）——新增季后赛小高潮。

### 3.7 周目标（P3）

挂接真实赛程的轻任务：
- "本周签约一名火热状态球员"、"预测命中 2 场"、"征战之路赢 5 场"。
- 每周刷新，奖励金币包 + 招募卡。
- 解决原版"中后期无事可做"。

## 四、经济设计（收敛版 r29）

单货币金币，沿用原版产出/消耗骨架，做三处调整：

| 调整 | 内容 |
|---|---|
| 抽卡消耗删除 | 金币不再有 200/300 抽卡出口，改为强化合卡与签约吃金币 |
| 合卡返还 | 失败返 1 材料，降低挫败 |
| 预测税 | 投注上限随等级缓升（防前期梭哈破产弃游），如 Lv1 上限 200 |

产出表沿用原版（开局 500 / 新手 1500 / 签到 2100 / PVE 50–100 / 预测 / 卖出），总量对账逻辑不变。

**广告点位（2 个，不锁主线）**：商店刷新、合卡幸运加成。全部走 `LampsGame.showRewardedVideo`，只认 `res.ok`。

## 五、平台架构（Lamps）

| 能力 | 实现 |
|---|---|
| 云存档 | `LampsPlatform.saveGameProgress/getGameProgress`，精简 payload（持仓存 id+版本+加成+数量；市场持仓存买价；全量存金币/赛季/注单/签到/任务） |
| 排行榜 | 战力榜 `gameRankType:"power"`、价值周榜 `"value-W<yyyyWww>"` 按周滚动；`dataLoad` 附阵容快照 |
| 激励视频 | `LampsGame.showRewardedVideo({source})` |
| 业务请求 | `window.LampsGame.request`（禁 fetch/XHR；响应 URL-encode；30s 超时） |
| 服务器接口 | 见 `01-迁移方案与服务器需求清单.md`：P0 仅 /cba/players、/cba/meta、/cba/games 三接口 |
| 本地兜底 | 内置 player-feed.json 静态目录；接口不可用时数据停更、玩法可玩 |

## 八、风险

1. Lamps 存档体积上限未知 → M1 实测。
2. 数据接口时效（完场后多久可拉）→ 影响开奖文案，等接口时确认。
3. 价值榜按周滚动的 `gameRankType` 需稳定字符串，跨年周编号要固定算法。
4. 状态层判定依赖数据质量：DNP（未出场无记录）与"没比赛"要区分，接口方需保证未出场球员当日返回空 stats 而非缺行。
